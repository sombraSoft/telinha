One container runs everything: the image `ghcr.io/sombrasoft/telinha`
(`linux/amd64` and `linux/arm64`) bundles `livekit-server`, Telinha's own
`caddy` build and `cloudflared`. The host keeps the compose file and the configuration in
`/opt/telinha`, and an optional timer, `telinha-update`, keeps it on the newest
stable release.

## Before you start

- A Linux machine with Docker Engine and the compose plugin, at home or on a
  VPS, and root access (`sudo`). Alpine and other musl systems belong here:
  the native build needs glibc.
- A Discord server where you can create an application and add a bot. You can
  create the app before the setup or while it runs: see
  [Discord app](/telinha/start/discord/).
- For the address people open: at home a domain on Cloudflare, or nothing (the
  setup gives you a free DuckDNS address); on a VPS your own domain, DuckDNS
  or sslip.io. [Address, HTTPS and ingress modes](/telinha/guides/domains/)
  compares them.
- At home, access to your router's admin page unless it does UPnP, and a line
  that is not behind CGNAT, unless LiveKit Cloud carries the video
  (`MEDIA=cloud`, with a Cloudflare Tunnel for the pages): see
  [CGNAT and double NAT](/telinha/guides/domains/#cgnat-and-double-nat) and
  [LiveKit Cloud](/telinha/guides/livekit-cloud/). No
  access and no UPnP, for example a locked ISP router or a shared building
  network? Then the machine cannot open the ports itself: ask the ISP or
  whoever runs the network to forward them, or use a [VPS](/telinha/start/vps/).

:::caution[Docker Desktop on Windows]
On Windows the [native install](/telinha/start/windows/) is the simpler path.
Docker Desktop also works: the compose file uses host networking, which needs
Docker Desktop 4.34 or newer with **Settings → Resources → Network → Enable
host networking** turned on. Video over UDP through that path is unverified, so
use a Cloudflare Tunnel or the DuckDNS option there (nothing to bind on
80/443).
`install-docker.sh` and `telinha-update` are Linux only.
:::

## Install

The installer needs root. Either pass `--docker` to the same one-liner the
native install uses:

```sh
curl -fsSL https://github.com/sombraSoft/telinha/releases/latest/download/install.sh | sudo sh -s -- --docker
```

or download the Docker bundle of the release and run its installer yourself:

```sh
curl -fsSLO https://github.com/sombraSoft/telinha/releases/latest/download/telinha-deploy.tar.gz
mkdir telinha-deploy && tar xzf telinha-deploy.tar.gz -C telinha-deploy && cd telinha-deploy
sudo sh install-docker.sh
```

The one-liner downloads `telinha-deploy.tar.gz`, checks it against the
release's `SHA256SUMS` and runs the `install-docker.sh` inside. That script can
run again at any time; it changes only what is its own:

| Path | What |
| --- | --- |
| `/opt/telinha/compose.yml` | One service, `telinha`, with host networking and the volume `telinha-data` for the data |
| `/opt/telinha/compose.journald.yml` | Optional override that sends the logs to journald |
| `/opt/telinha/compose.override.yml` | Yours, optional; compose picks it up by itself |
| `/opt/telinha/config/telinha.env` | The configuration, created from the example only when missing (mode 600) |
| `/opt/telinha/.env` | The version compose runs, written by `telinha-update` (without it, `latest`) |
| `/usr/local/sbin/telinha-update` | The updater, with its systemd units in `/etc/systemd/system/` |

`/opt/telinha` is root's (mode 700), so the commands on this page run in a root
shell: `sudo -i` first. With `TELINHA_VERSION=<tag>` the installer pins compose
to that release.

By hand without the installer: create `/opt/telinha/config`, copy
`compose.yml` (in the bundle, or `deploy/` of a clone) to `/opt/telinha/` and
`telinha.env.example` to `/opt/telinha/config/telinha.env`, fill it in (the
example lists every key with a comment), then `docker compose up -d`.

## Run the setup

While `telinha.env` still has empty values, the installer offers the setup. It
runs inside the image, so nothing else gets installed on the host. To run it
yourself later:

```sh
docker run --rm -it --user 0 -e TELINHA_HOME=/telinha -v /opt/telinha/config:/telinha/config ghcr.io/sombrasoft/telinha:latest setup --docker
```

`-it` is required: the setup draws full-screen screens and reads your keys, so
it needs the terminal. Without it (a script, a pipe) the same command prints
plain lines and takes every answer from flags and the environment, see
[Command line](/telinha/reference/cli/#telinha-setup).

The screens show the steps down the left (Where, Address, Discord, Ports,
Review, Install; there is no Updates step in Docker, `telinha-update` does that
job), the current question as a card on the right and a hint that explains the
choice. Discord servers, roles and channels come from lists. A first run starts with the
language, English or Brazilian Portuguese. It works from 80 columns by 24 rows,
and the keys are the same as in the other installs: ↑ ↓ and Enter or the number
of an option answer, Esc or ← goes back, Tab jumps to a step already answered,
secrets show as dots (paste, Ctrl+R shows or hides them) and Ctrl+C quits.
[Command line](/telinha/reference/cli/#keys) lists every key.

<Steps>

1. **Where.** *Where will Telinha run?* Answer for the machine the container
   runs on: *A computer at home* (your PC or another machine at home) or *A
   rented machine (VPS)*.

2. **Address.** At home, where connections usually do not let the web ports
   80 and 443 in, it asks *Do you have a domain on Cloudflare?*: yes gives a
   Cloudflare Tunnel, no gives a free DuckDNS address with HTTPS on port 8443
   (`https://my-group.duckdns.org:8443`, the certificate comes through
   DuckDNS). On a VPS it asks *How will people reach Telinha?*: your own
   domain, DuckDNS or sslip.io on 80 and 443, a Cloudflare Tunnel or your own
   reverse proxy.

3. **Discord.** Paste the bot token: it is checked with Discord right away and
   your app is read from it. Then the client secret, the Discord server, the role that
   may enter, the channels and the command name, all from lists. When the app
   does not have the login redirect yet, a card shows the address to add under
   OAuth2 → Redirects, the one thing you do by hand on the Developer Portal.
   [Discord app](/telinha/start/discord/) walks through every screen.

4. **Video.** *Where does the video go through?* Keep *This computer*.
   *LiveKit Cloud* is for a connection that nothing from the internet can
   reach (CGNAT, which the setup detects and then picks Cloud for you): it
   asks the project's URL, API key and secret, and there are no media ports to
   open; see [LiveKit Cloud](/telinha/guides/livekit-cloud/). On a VPS with
   the address on 443 it also offers to serve video through port 443 for
   strict networks ([TURN over TLS](/telinha/guides/turn/)).

5. **Ports.** TCP 7881 and UDP 7882 carry the video. Keep them unless
   something else on the host uses them. At home it then asks whether Telinha
   may open the ports on the router through UPnP (it works from the container,
   thanks to host networking).

6. **Review.** Every answer on one screen, grouped by step; choose *Apply* to
   write `/opt/telinha/config/telinha.env` (mode 600), or go back to change
   something. Nothing is written before that.

7. **Install.** Docker's list is short: the Discord app is checked (and its
   intents switched on), the DuckDNS address is updated if you picked one, and
   the file is written. No programs to download, no service, no firewall, no
   router probe. If a task fails the screen offers *Retry*, *Skip* or *Back to
   questions*, as in the other installs (no *Skip* when the file itself cannot
   be written). The last card shows the file it wrote
   and how to start:

   ```sh
   cd /opt/telinha && docker compose up -d
   ```

   or, to let `telinha-update` deploy it now and keep it updated from then on:

   ```sh
   systemctl enable --now telinha-update.timer
   ```

</Steps>

## Open the ports

The container uses the host's network, so the ports are the host's:

| Port | When | What for |
| --- | --- | --- |
| TCP 7881 | always | Video over TCP, for networks that block UDP |
| UDP 7882 | always | Video over UDP, the normal path |
| TCP 8443 | at home, DuckDNS address (your port if you changed it) | The pages, over HTTPS |
| TCP 443 | on a VPS, your own domain, DuckDNS or sslip.io | The pages, over HTTPS |
| TCP 80 | on a VPS, same | The Let's Encrypt challenge and the redirect to HTTPS |

At home that is all: never 80 or 443. With a Cloudflare Tunnel only the two
media ports are needed (tunnels do not carry WebRTC). If you changed a port in
the setup, use your value.

**At home**, UPnP comes first: when it is on (`UPNP=auto`) and the router
accepts it, Telinha maps these ports while it runs. Otherwise forward them by
hand to the host's local IP; see [Port forwarding](/telinha/guides/port-forwarding/)
and the pages for [Vivo](/telinha/routers/vivo/), [Claro](/telinha/routers/claro/),
[TIM](/telinha/routers/tim/) and [Oi](/telinha/routers/oi/) routers. **On a
VPS**, open them in the provider's firewall (see [VPS](/telinha/start/vps/)).

If ufw or firewalld is active on the host, open the same ports there. At home
with a DuckDNS address (drop `8443/tcp` with a tunnel):

```sh
sudo ufw allow 7881/tcp && sudo ufw allow 7882/udp && sudo ufw allow 8443/tcp
sudo firewall-cmd --permanent --add-port=7881/tcp --add-port=7882/udp --add-port=8443/tcp && sudo firewall-cmd --reload
```

On a VPS with the bundled Caddy:

```sh
sudo ufw allow 7881/tcp && sudo ufw allow 7882/udp && sudo ufw allow 443/tcp && sudo ufw allow 80/tcp
sudo firewall-cmd --permanent --add-port=7881/tcp --add-port=7882/udp --add-port=443/tcp --add-port=80/tcp && sudo firewall-cmd --reload
```

## Check it

Doctor runs inside the container:

```sh
docker exec -it telinha bun server/src/index.ts doctor
```

With `-it` it is a checklist, one row per check with a spinner until it has its
result: press Enter on a row to see its detail and, when it is not ok, the fix,
and `r` to run every check again (the `gateway`, `cgnat` and `mappings` rows
tell you what the router agreed to). When the checks are done a panel shows a
link and a QR code for the phone test: open it on your phone with Wi-Fi off, so
the test comes from outside your network. It tells you whether the page, the
LiveKit connection, UDP and TCP all work from there, and `p` starts a new test.
Without `-it` it prints the table. [Doctor and troubleshooting](/telinha/guides/doctor/)
explains every row and what a failure means.

The container also has a healthcheck: `docker compose ps` shows it unhealthy
while a bundled program is down, for example a Caddy that cannot bind its port
or a bad tunnel token.

## Use it

Type `/telinha` (or the command name you chose) in one of the channels you
picked. The bot posts a card with a button to a new room at
`https://<your address>/r/<code>`. Whoever opens it logs in with Discord once,
and members with the role get in. Share your screen from Chrome, Edge or
another Chromium browser; watching works on phones too. The card shows who is
streaming and, while someone streams, who else is in the room. The room closes
by itself a few minutes after everyone leaves.

## Day two

Compose's `restart: unless-stopped` is the service: the container comes back
after a crash or a reboot.

```sh
docker logs -f telinha
cd /opt/telinha && docker compose restart
```

To keep the logs in the journal across container re-creations, use the
journald override, then read them with `journalctl`:

```sh
cp /opt/telinha/compose.journald.yml /opt/telinha/compose.override.yml
cd /opt/telinha && docker compose up -d
journalctl -t telinha
```

**Updates.** With the timer on, `telinha-update` checks 3 minutes after boot and
then every 5 minutes, verifies the image against the digest published with the
release, waits while rooms are open and rolls back a version that never turns
healthy. Without it, update by hand with
`docker compose pull && docker compose up -d` in `/opt/telinha`.

```sh
telinha-update status
telinha-update --now
```

See [Updates](/telinha/guides/updates/) for pinning a version and the other
subcommands.

**Changing settings** means running the setup again (the `docker run` line
above, or `sh install-docker.sh --setup` from the bundle) and re-creating the
container so it reads the new file:

```sh
cd /opt/telinha && docker compose up -d --force-recreate
```

[Running as a service](/telinha/guides/service/) covers the override file, a
memory limit and the healthcheck.
