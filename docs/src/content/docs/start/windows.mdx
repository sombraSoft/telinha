The PC you already have is enough. One PowerShell line installs Telinha, the
setup screens ask a few questions, and a background task keeps it running
from boot, whether or not anyone is logged on.

## Before you start

- A 64-bit Windows PC, x64 or ARM, with Windows PowerShell 5.1 (built into
  Windows) or a newer PowerShell.
- The PC stays on, because a sleeping PC closes every room. Set it never to
  sleep while plugged in: Settings → System → Power & battery (Power on a
  desktop) → Screen and sleep (Screen, sleep & hibernate timeouts on newer
  builds) → *When plugged in, put my device to sleep after*: *Never*.
- A Discord server where you can create an application and add a bot. You can
  create the app before the setup or while it runs: see
  [Discord app](/telinha/start/discord/).
- For the address people open: a domain on Cloudflare, or nothing, in which
  case setup gives you a free DuckDNS address.
  [Address, HTTPS and ingress modes](/telinha/guides/domains/) compares the
  two.
- Access to your router's admin page, unless it does UPnP (many routers ship
  with it off, and ISP routers often hide the switch). Telinha never needs
  ports 80 or 443 at home: only the two media ports, plus 8443 with a DuckDNS
  address.
  No access and no UPnP, for example a locked ISP router or a shared building
  network? Then this PC cannot open the ports itself: ask the ISP or
  whoever runs the network to forward them, or use a [VPS](/telinha/start/vps/).
  If your line is behind CGNAT, nothing from the internet reaches the PC:
  read [CGNAT and double NAT](/telinha/guides/domains/#cgnat-and-double-nat)
  first.

## Install

<Steps>

1. Press Start, type `PowerShell` and click **Windows PowerShell**, not *Run
   as administrator*: Telinha installs into your own user folder, and the
   setup asks for administrator rights by itself when it needs them.

2. Paste this line and press Enter:

   ```powershell
   irm https://github.com/sombraSoft/telinha/releases/latest/download/install.ps1 | iex
   ```

3. The script downloads `telinha-windows-x64.zip` (or `telinha-windows-arm64.zip`)
   and `SHA256SUMS` from the newest stable release and stops if the sha256 does
   not match. It puts `telinha.exe` and the tray icon `telinha-tray.exe` into
   `%LOCALAPPDATA%\Telinha\bin`, adds that folder to your user `PATH`, prints
   `telinha --version` and starts `telinha setup`.

</Steps>

The script downloads nothing else. The setup downloads `livekit-server` and
`cloudflared` from upstream, each checked against a pinned sha256, and
`caddy` from the same Telinha release, checked against its `SHA256SUMS`.

Three environment variables change what the script does. Set them in the same
window before the `irm` line:

```powershell
$env:TELINHA_VERSION = 'vX.Y.Z'
$env:TELINHA_HOME = 'D:\Telinha'
$env:TELINHA_NO_SETUP = '1'
```

`TELINHA_VERSION` installs that release tag instead of the newest one,
`TELINHA_HOME` uses another folder (kept as a user variable so later
terminals find it), and `TELINHA_NO_SETUP` installs without starting the
setup. Downloading the zip from the releases page by hand works too: unpack it
anywhere and double-click `telinha.exe`, which offers the setup when there is
no configuration yet. A code-signed release names its publisher when Windows
asks about it; an unsigned build may be stopped by SmartScreen's *Windows
protected your PC*: click *More info*, then *Run anyway*.
[Code signing](/telinha/guides/code-signing/) shows how to tell which one you
have.

:::note
On Windows on ARM, Telinha runs the arm64 build. Cloudflare publishes no ARM
`cloudflared` for Windows, so the tunnel mode uses the x64 one under emulation.
:::

## Run the setup

Setup fills the PowerShell window with its own screens: the steps down the left
(Where, Address, Discord, Ports, Updates, Review, Install), the current
question as a card on the right and, beside or under it, a hint that explains
the choice. Servers, roles and channels come from lists, so you never copy an
id by hand. A first run starts with the language, English or Brazilian
Portuguese, and every screen switches at once.

- **Answer** with ↑ ↓ and Enter, or press the number of an option. For a text
  answer, type and press Enter.
- **Go back** with Esc or ←. The answers you gave stay.
- **Jump** with Tab: ↑ ↓ and Enter go to any step you have already answered,
  and Esc returns to the card.
- **Secrets** (tokens) show as dots. Paste with Ctrl+V or your terminal's
  paste shortcut, and press Ctrl+R to show or hide what you pasted.
- **Quit** with Ctrl+C. Nothing is written until you apply at the Review.

[Command line](/telinha/reference/cli/#keys) lists every key. On a Windows PC
at home it goes like this:

<Steps>

1. **Where.** The hint shows the public IP and the router, if one answers
   UPnP, NAT-PMP or PCP. Choose *A computer at home (a PC or a home server)*
   for *Where will Telinha run?*

2. **Address.** Home internet connections usually do not let the web ports
   80 and 443 in, so Telinha does not count on them. It asks *Do you have a
   domain on Cloudflare?*

   - *Yes: use a Cloudflare Tunnel.* Your own address, and nothing to open
     for the pages. You paste the tunnel's token and its public hostname; see
     [Cloudflare Tunnel](/telinha/guides/domains/#cloudflare-tunnel).
   - *No: use a free DuckDNS address.* You sign in on duckdns.org, add a name
     and paste the token, which is tried at once. Telinha serves HTTPS on port
     8443 (you can pick another) and gets the certificate through DuckDNS, so
     the address looks like `https://my-group.duckdns.org:8443` and the links
     carry the port. Some strict networks (offices, schools) only let browsers
     reach port 443, so people there cannot open them; a domain on Cloudflare
     has no such limit. See
     [DuckDNS on port 8443](/telinha/guides/domains/#duckdns-on-port-8443).

3. **Discord.** Paste the bot token: Telinha checks it with Discord right
   away and reads your app from it. Then the client secret (also checked), the
   server (a list of the ones the bot is in; *Another server* shows an invite
   link and checks again once you added the bot), the role that may enter, the
   channels (Space marks one, `a` marks all) and the command name. A group
   name is optional. When the app does not have the login redirect yet, a card
   shows the address to add under OAuth2 → Redirects, the one thing you do by
   hand on the Developer Portal: add it, press Save Changes there, then choose
   *I added it: check again*. [Discord app](/telinha/start/discord/) walks
   through every screen.

4. **Video.** *Where does the video go through?* Keep *This computer*.
   *LiveKit Cloud* is for a connection that nothing from the internet can
   reach (CGNAT, which the setup detects and then picks Cloud for you): it
   asks the project's URL, API key and secret, and there are no media ports to
   open; see [LiveKit Cloud](/telinha/guides/livekit-cloud/).

5. **Ports.** TCP 7881 and UDP 7882 carry the video. Keep them unless
   something else on the PC uses them. Then *Ask the router?*: say yes to let
   Telinha ask the router for the ports through UPnP, or no if you will
   forward them yourself.

6. **Updates.** Say yes: new stable releases then install themselves when no
   room is open.

7. **Tray icon.** *Show a Telinha icon next to the clock?* Say yes: the
   [tray icon](/telinha/guides/tray/) shows whether Telinha is running and
   opens the room page, the logs and updates. When you say yes, *Start the
   icon when you sign in to Windows?* decides whether it comes back by itself
   after a restart (no by default; `telinha tray start` shows it any time).

8. **Review.** Every answer on one screen, grouped by step, with the web
   address highlighted and secrets shown only as set, kept or generated. Page
   with PgUp and PgDn when the list is long. Choose *Apply* (or *Apply with a
   new cookie secret*, offered on a re-run, which logs everyone out of the
   pages), *Back to the questions* or *Quit without writing*. Nothing has
   changed on this PC until you apply.

9. **Install.** A live list: the Discord app (checked, and its intents
   switched on), the DuckDNS address if you picked one, `telinha.env`, the
   helper programs (with a bar for each download), the service, the tray icon,
   the router and firewall, the start, the HTTPS certificate (with a DuckDNS address) and the
   final checks. The file goes to `%LOCALAPPDATA%\Telinha\config\telinha.env`,
   readable only by you, SYSTEM and Administrators. The service row is where
   Windows asks for administrator rights once (UAC), to register the
   background task and add the firewall rules; the row says it is waiting for
   you. The tray icon appears next to the clock right after it (it starts only
   when the setup runs from a normal terminal, not an administrator one). The router row looks at the router (warning about CGNAT or double NAT,
   listing the ports to forward by hand without UPnP), then Telinha starts and
   its certificate arrives. At the end the screen shows your web address, and
   *Show the doctor report* opens the checklist with the phone test.

</Steps>

If a task fails, its lines open under it with a hint, and three choices:
*Retry* runs it again, *Skip* leaves it and goes on with the rest (the
final checks then tell you what is missing), and *Back to questions* returns
to the question that task depends on (the bot token for the Discord app, the
DuckDNS token for DuckDNS) or to the Review; apply again from there and the
secrets generated before stay the same. Writing telinha.env has no *Skip*:
everything after it needs the file; once it is written, the Review says so and
its last choice is *Leave setup*. ↑ from the choices walks the finished rows,
and Enter shows what each did. The last card opens what is left to do by hand
(the router's ports, a warning's command), and the summary left in the terminal
lists it too. Going back is off while a task runs, and Ctrl+C asks for a second
press, because stopping half way can leave a half install.

:::note[The administrator prompt]
Windows shows a User Account Control prompt for `telinha.exe`. A code-signed
release shows its publisher; an unsigned build shows *Publisher: Unknown*,
which is expected for it (see [Code signing](/telinha/guides/code-signing/)).
Either way, check that the program is the one in `%LOCALAPPDATA%\Telinha\bin`
(*Show more details* shows the path) and click **Yes**.
:::

:::note[Forwarding the ports by hand?]
When no router answered UPnP (or you did not allow it), the router row only
lists the ports to forward and the install carries on, so the phone test fails
in the doctor report. That is expected: forward the ports as in
[Open the ports](#open-the-ports) below, then run `telinha doctor` again. The
certificate does not wait for them: with a DuckDNS address it comes through
DuckDNS (usually 1-3 minutes), and with a tunnel Cloudflare holds it.
:::

If you said no to the UAC prompt, the service row fails and shows a PowerShell
command that asks again. *Retry* asks right away, and running `telinha setup`
once more does the same.

Without a terminal, or with `--non-interactive`, setup prints plain lines and
takes every answer from flags, the environment and the existing file: see
[Command line](/telinha/reference/cli/#telinha-setup).

## Open the ports

The internet has to reach the PC on these ports:

| Port | When | What for |
| --- | --- | --- |
| TCP 7881 | always | Video over TCP, for networks that block UDP |
| UDP 7882 | always | Video over UDP, the normal path |
| TCP 8443 | DuckDNS address (your port if you changed it) | The pages, over HTTPS |

Nothing more: not 80, not 443. With a Cloudflare Tunnel only the two media
ports are needed (tunnels do not carry WebRTC). If you changed a port in the
setup, use your value.

**UPnP first.** When the router answered and you allowed it, Telinha asks the
router for these ports while it runs and you have nothing to do. Otherwise
forward them by hand to the PC's local IP, after giving the PC a fixed address
so the rule keeps pointing at it.
[Port forwarding](/telinha/guides/port-forwarding/) explains both, and there
are pages for [Vivo](/telinha/routers/vivo/), [Claro](/telinha/routers/claro/),
[TIM](/telinha/routers/tim/) and [Oi](/telinha/routers/oi/) routers.

**Windows Firewall.** The UAC step adds inbound rules, each bound to its
program in `bin\`: `Telinha LiveKit TCP` and `Telinha LiveKit UDP` for
`livekit-server.exe`, and with a DuckDNS address `Telinha HTTPS` for
`caddy.exe` on 8443. There is no `Telinha HTTP` rule at home: nothing listens
on port 80. Running `telinha` in a console
before the service and dismissing the Windows Security alert leaves Block
rules behind, and Block wins over Allow; the install removes those first. Run
`telinha setup` again after changing a port so the rules follow.

## Check it

```powershell
telinha doctor
```

Doctor is a checklist: one row per check, each with a spinner until it has its
result. Press Enter on a row to see its detail and, when it is not ok, the fix;
`r` runs every check again after you fix something. When the checks are done a
panel shows a link and a QR code for the phone test: open it on your phone with
Wi-Fi off, so the test comes from outside your network like your friends'
connections do. It tells you whether the page, the LiveKit connection, UDP and
TCP all work from there, and `p` starts a new test. `telinha doctor --local`
skips the checks that need the internet.
[Doctor and troubleshooting](/telinha/guides/doctor/) explains every row and
what a failure means.

## Use it

Type `/telinha` (or the command name you chose) in one of the channels you
picked. The bot posts a card with a button to a new room at
`https://<your address>/r/<code>`. Whoever opens it logs in with Discord once,
and members with the role get in. Share your screen from Chrome, Edge or
another Chromium browser; watching works on phones too. The card shows who is
streaming and, while someone streams, who else is in the room. The room closes
by itself a few minutes after everyone leaves.

:::caution[It works for friends but not from your own network?]
Many routers cannot send a connection to their own public address back inside
(NAT loopback, also called hairpin NAT or NAT reflection). Then the room opens
on mobile data and for everyone outside, but not from this PC or another
device on your network. Turn NAT loopback on if the router has the option.
A hosts-file line pointing the name at the PC's local IP does not fix it:
the page loads, but LiveKit still announces the public IP for the video. See
[Doctor and troubleshooting](/telinha/guides/doctor/#works-from-outside-but-not-from-your-own-network).
:::

## Day two

The background task is called `Telinha` in Task Scheduler. It starts at boot,
runs as your account without administrator rights, starts Telinha again after
an update or a crash, and writes the log to
`%LOCALAPPDATA%\Telinha\logs\telinha.log` (rotated at 10 MB, five kept).

```powershell
telinha service status
telinha service restart
telinha service stop
telinha service start
Get-Content "$env:LOCALAPPDATA\Telinha\logs\telinha.log" -Tail 50 -Wait
```

`telinha run` starts Telinha in the console instead (Ctrl+C stops it), but only
one copy runs per home folder: with the service up, a console run says
`Telinha is already running` and exits.

**The tray icon** next to the clock shows whether Telinha is running and
starts, stops and restarts it, checks for updates and opens the page and the
log. It does not come back at sign-in unless you turn on *Start with Windows*
in its menu (or run `telinha tray autostart on`); after *Quit*,
`telinha tray start` brings it back. See [Tray icon](/telinha/guides/tray/).

**Updates** happen on their own: Telinha checks a few minutes after it starts
and then every few hours, waits while rooms are open, checks the sha256 and
rolls back a version that fails to start. `telinha update --check` shows where
you stand and `telinha update --now` installs at once. See
[Updates](/telinha/guides/updates/).

**Changing settings** means running `telinha setup` again: every question
starts at the current value, secrets can be kept (Enter keeps them), and the service restarts with
the new file. Editing `telinha.env` by hand works too, followed by
`telinha service restart`.

**Removing it**: `telinha service uninstall --firewall` removes the task and
the firewall rules, closes the tray icon and removes its *Start with Windows*
entry; then delete `%LOCALAPPDATA%\Telinha`.

[Running as a service](/telinha/guides/service/) has the details.
